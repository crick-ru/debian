# aml (crick Debian backports)

`aml` 1.0.0 — библиотека цикла событий Андрея Хинса для Debian 13
(trixie, amd64).

Версия: `1.0.0-1+crick`.

Упаковка взята из Debian (`aml_1.0.0-1`) и переработана.

## Зачем он здесь

`aml` сам по себе ничему не нужен — он в списке пакетов этого репозитория
только потому, что от него зависят два других:

```
wayvnc 0.10.1  ->  libaml-dev (>= 1.0.0)
neatvnc 1.0.1  ->  libaml-dev (>= 1.0.0)
```

В trixie `aml` версии 0.3.0, и к тому же он называется `libaml0t64`
(суффикс `t64` из-за перехода на time64). Обе цифры не подходят: версия ниже
требования, а имя пакета другое. Поэтому здесь публикуется `libaml1` —
новое имя рядом со старым `libaml0t64`.

## Что публикуется

| Пакет | Что внутри |
|---|---|
| `libaml1` | `libaml.so.1` |
| `libaml-dev` | `aml.h`, `libaml.so`, `aml.pc` |

## Что отключено

- примеры (`examples/`) не собираются: опция `-Dexamples` по умолчанию `false`,
  файлы примеров (`libaml-dev.examples` у Debian) удалены;
- README не ставится в `/usr/share/doc`;
- dbgsym-пакеты не собираются (общее правило `scripts/build-package.sh`).

Символьных файлов нет: библиотека маленькая, `dh_makeshlibs` генерирует
`shlibs` сам. SONAME `libaml.so.1` не меняется, удалённых символов нет.

## Что произойдёт при `apt upgrade`

`libaml0t64` от trixie **останется установленным**: у него другое имя, apt
не считает его нашим пакетом и не удаляет. Он просто перестанет
использоваться — его заменит `libaml1`. Если в системе стоит штатный
`neatvnc`/`wayvnc` из trixie, они продолжат работать со старым `libaml0t64`
(у них разные SONAME), а наши `libneatvnc1` и `wayvnc` будут использовать
`libaml1`.

Убрать лишнее вручную после установки нашего набора:

```bash
sudo apt autoremove
```

## Откат

```bash
sudo apt remove libaml1 libaml-dev
```
