# aml

Библиотека цикла событий (`libaml`) для Debian 13 (trixie, amd64).

## Источник упаковки

Упаковка взята из Debian (`aml_1.0.0-1`, ветка unstable) и переработана.
Tarball побайтово совпадает с Debian-овским `aml_1.0.0.orig.tar.xz`.

## Версии

- **В trixie:** 0.3.0 (пакет `libaml0t64`)
- **В исходной упаковке:** 1.0.0-1
- **В нашем репозитории:** 1.0.0-1+crick

Версия 0.3.0 из trixie ниже требований `wayvnc` и `neatvnc` (>= 1.0.0),
а имя пакета `libaml0t64` отличается от нашего `libaml1` (новое имя
без суффикса `t64`).

## Содержимое

| Пакет | Содержимое |
|---|---|
| `libaml1` | `libaml.so.1` |
| `libaml-dev` | `aml.h`, `libaml.so`, `aml.pc` |

## Что изменено

- Примеры (`examples/`) не собираются: опция `-Dexamples` по умолчанию `false`,
  файлы примеров (`libaml-dev.examples` у Debian) удалены.
- README не ставится в `/usr/share/doc`.
- dbgsym-пакеты не собираются (общее правило `scripts/build-package.sh`).

SONAME `libaml.so.1` не меняется, удалённых символов нет. Символьных файлов
нет: библиотека маленькая, `dh_makeshlibs` генерирует `shlibs` сам.

## Важные нюансы

`aml` публикуется не сам по себе — он нужен `wayvnc 0.10.1` и
`neatvnc 1.0.1`, которые требуют `libaml-dev (>= 1.0.0)`. В trixie версия
0.3.0 и имя `libaml0t64`, поэтому без собственной сборки их нельзя собрать
против crick-репозитория.

Пакет `libaml0t64` из trixie остаётся установленным: у него другое имя,
apt не считает его нашим пакетом и не удаляет. Его заменит `libaml1`.
