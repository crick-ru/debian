# wayvnc (crick Debian backports)

`wayvnc` 0.10.1 — VNC-сервер для Wayland-композиторов на wlroots — для
Debian 13 (trixie, amd64).

Версия: `0.10.1-1+crick`.

Упаковка взята из Debian (`wayvnc_0.10.1-1`, ветка unstable) и переработана.

## Что это

VNC-сервер, который подключается к работающей сессии Wayland, создаёт
виртуальные устройства ввода и отдаёт один дисплей по протоколу RFB. Сессия
может быть headless — тогда wayvnc работает вообще без физического экрана.
В репозитории рядом лежит `labwc` (композитор на wlroots), так что связка
`labwc + wayvnc` — рабочий сценарий удалённого доступа к сессии.

## Почему версия 0.10.1, а не 0.9.1

В trixie `wayvnc` 0.9.1. Апстрим с тех пор выпустил 0.10.0 и 0.10.1, но
0.10.x требует двух библиоц, которых в trixie нет:

```
libaml-dev (>= 1.0.0)      в trixie aml 0.3.0
libneatvnc-dev (>= 1.0.0)   в trixie neatvnc 0.9.1
```

Поэтому вместе с wayvnc в репозиторий добавлены `aml` и `neatvnc` — это
не «побочные» пакеты, а обязательные сборочные зависимости.

## Что изменено по сравнению с Debian

| Что | Debian | Здесь | Зачем |
|---|---|---|---|
| man-страницы | `scdoc` в Build-Depends, страницы генерируются | `-Dman-pages=disabled`, `scdoc` убран | правило «man-страниц нет» |
| тесты | в апстриме включены по умолчанию (`tests: true`) | `-Dtests=false` | правило «тесты не собираются» |
| TLS-зависимость | `gnutls-dev` (виртуальный пакет) | `libgnutls28-dev` | реальное имя пакета |

## Почему стадия 6

wayvnc — приложение, а не библиотека: ни один пакет этого репозитория не
собирается против него. По правилу расстановки стадий приложение собирается
в последней стадии.

## X11, диски, DVB, VDPAU

Ничего из этого в wayvnc не отключается — таких возможностей у него нет.
wayvnc работает только с Wayland-протоколами (wlr-export-dmabuf,
wlr-screencopy, xdg-output, wlr-output-management, …), DRM/GBM и
аппаратным кодированием H.264 через libavcodec. Ни одного из этих протоколов
X11 он не использует, поэтому проверка

```bash
grep -rniE 'libx(11|ext|render)|libxcb|x11proto|x11-xkb|xvfb|xwayland' \
  packages/wayvnc/debian/control
```

даёт пустой результат.

Пакет собирается против наших `libwayland`, `libdrm`, `libpixman-1`,
`libxkbcommon` — тех, что без X11-составляющей.

## Примеры конфигурации

`debian/wayvnc.examples` публикует `auto-attach.py`, `event-watcher` и
`single-output-sway` — это готовые скрипты, которые пользователь кладёт рядом
с конфигом wayvnc, а не документация. Поэтому они сохраняются вопреки общему
правилу «примеры не публикуются» (исключение для конфигурационных файлов в
правилах репозитория).
