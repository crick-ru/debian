# wayvnc

VNC-сервер для Wayland-композиторов на базе wlroots.

## Источник упаковки

Упаковка взята из Debian (`wayvnc_0.10.1-1`, ветка unstable) и переработана.
Tarball побайтово совпадает с Debian-овским `wayvnc_0.10.1.orig.tar.gz`.

## Версии

- **В trixie:** 0.9.1-1
- **В исходной упаковке:** 0.10.1-1
- **В нашем репозитории:** 0.10.1-1+crick (ревизия 1)

## Содержимое

| Пакет | Содержимое |
|---|---|
| `wayvnc` | `usr/bin/wayvnc` — VNC-сервер |

Один бинарный пакет — приложение, а не библиотека.

## Важные нюансы

### Зачем нужен

`wayvnc 0.10.1` требует `libneatvnc-dev (>= 1.0.0)` и `libaml-dev (>= 1.0.0)`,
а в trixie есть только neatvnc 0.9.1 и aml 0.3.0. Поэтому вместе с wayvnc
в репозиторий добавлены `aml` и `neatvnc` — это обязательные сборочные
зависимости, а не побочные пакеты.

### Стадия сборки

wayvnc — приложение, а не библиотека: ни один пакет репозитория не собирается
против него. По правилу расстановки стадий приложения собираются в последней
стадии.

### X11 в wayvnc

`grep -rniE 'libx(11|ext|render)|libxcb|x11proto|x11-xkb|xvfb|xwayland'` в
`debian/control` даёт пустой результат — у wayvnc нет X11-зависимостей.
Он работает только с Wayland-протоколами, DRM/GBM и аппаратным кодированием
H.264 через libavcodec.

### Примеры конфигурации

`debian/wayvnc.examples` публикует `auto-attach.py`, `event-watcher` и
`single-output-sway` — это готовые скрипты для размещения рядом с конфигом,
а не документация. Сохраняются вопреки общему правилу «примеры не
публикуются» (исключение для конфигурационных файлов).

### Сборка против наших пакетов

`wayvnc` собирается против наших `libwayland`, `libdrm`, `libpixman-1`,
`libxkbcommon` — тех, что без X11-составляющей. `neatvnc` и `aml` берутся
из этого же репозитория.
