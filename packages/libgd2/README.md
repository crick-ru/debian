# libgd2 (crick Debian backports)

Сборка `libgd` 2.3.3 для Debian 13 (trixie, amd64).

Версия: `2.3.3-15+crick`.

Упаковка взята из Debian (`libgd2_2.3.3-14`, unstable) и переработана.

Каталог называется `libgd2`, хотя речь шла о `libgd3`: `libgd3` — это бинарный
пакет, а имя каталога обязано совпадать с именем **исходного** пакета Debian,
иначе `dpkg-source` ищет `../libgd2_2.3.3.orig.tar.gz` и не находит его
(та же ловушка, что с `gtk+3.0`).

## Что публикуется

| Пакет | Что внутри |
|---|---|
| `libgd3` | `libgd.so.3` — единственная библиотека |
| `libgd-dev` | заголовки, `libgd.pc`, `libgd.a`, `.so` для линковки |

`libgd-tools` не публикуется: это примеры (`gddemo`, `gdtest`, `testac`) плюс
man-страница на них. Правило репозитория — примеры и документация не собираются.

## Почему ревизия 15, а не 1

В trixie лежит `2.3.3-14~deb13u1`. Наша `2.3.3-1+crick` отсортировалась бы как
**старая** (`1 < 14`), и `apt upgrade` никогда бы её не подхватил. Поэтому
`REVISION=15` в `scripts/upstream/libgd2.conf`: Debian-ревизия нашей сборки
обязана быть не меньше ревизии trixie плюс единица. Это общее правило репозитория
(«ревизия — механизм доставки переработанной упаковки»), просто здесь его
значение задано не «2», а «15».

## X11 выключен — и почему php от этого не ломается

`libxpm4` входит в список зависимостей, которые репозиторий запрещает
(`libxpm` — это `libXpm`, а через неё тянется `libX11`). В trixie
`libgd3` Depends: `libxpm4`, то есть штатная сборка тянет X11.

У нас: `--without-xpm`, из `Build-Depends` и `Depends: libgd-dev` убраны
`libx11-dev` и `libxpm-dev`.

**Ключевой момент — ABI не ломается.** Единственный X11-символ в `libgd` —
`gdImageCreateFromXpm`. Апстрим при отсутствии `HAVE_LIBXPM` оставляет
заглушку (`src/gdxpm.c`, ветка `#ifndef HAVE_LIBXPM`): функция возвращает
`NULL` и печатает «libgd was not built with xpm support». Символ экспортируется,
SONAME остаётся `libgd.so.3`, `libgd3.symbols` менять не нужно.

Что это значит для `php8.4-gd` из trixie (проверено на самом `.deb`):

| Проверка | Результат |
|---|---|
| `php8.4-gd` Depends | `libgd3 (>= 2.3.3)` — **без пина версии**, наша `2.3.3-15+crick` подходит |
| `NEEDED` в `gd.so` | только `libgd.so.3` и `libc.so.6` — никаких `libXpm.so.4` |
| X11-символы, которые зовёт `gd.so` | ровно один: `gdImageCreateFromXpm` — и он у нас есть |
| Функциональная потеря | `imagecreatefromxpm()` в PHP вернёт `false` с предупреждением; остальное не затронуто |

Вывод: PHP мы в репозиторий не добавляем, но после `apt upgrade` на нашу
`libgd3` он продолжает грузиться и работать. Единственное, что перестаёт
работать, — чтение XPM-файлов, что для PHP-сценариев на веб-сервере не имеет
значения. Если бы заглушки в апстриме не было, пришлось бы либо оставить
`libxpm4`, либо признать поломку SONAME — оба варианта хуже.

Проверить на своей машине после публикации:

```bash
php -r 'var_dump(gd_info());'          # модуль загрузился
php -r '$i=imagecreatetruecolor(8,8); var_dump(imagepng($i));'  # png работает
```

## Что ещё выключено

- `--without-raqm` — как в Debian (raqm ломает вертикальный текст);
- тесты не собираются и не запускаются: каталог `debian/tests` удалён,
  `override_dh_auto_test` пуст;
- примеры и man-страницы не публикуются;
- dbgsym-пакеты не собираются (общее правило `scripts/build-package.sh`),
  поэтому `override_dh_strip` с миграцией `libgd-dbg` убран;
- quilt-патчи Debian оставлены все шесть, включая правящие `tests/`
  (`0002`, `0003`): без них дерево не накладывается, а на символы они не
  влияют.

## Что произойдёт при `apt upgrade`

Наша версия `2.3.3-15+crick` выше и `2.3.3-14~deb13u1` из trixie, и
security-версии: `15 > 14`, а `+crick` сравнивается с `~deb13u1` как большая
(`~` меньше всего, даже конца строки).

Побочные эффекты, которые надо проверить заранее:

1. `libgd-dev` из trixie Depends: `libgd3 (= 2.3.3-14~deb13u1)` — точной версии,
   которой у нас нет, поэтому apt **снимет** `libgd-dev` из trixie и поставит
   наш. Набор `-dev`-пакетов у нас свой (см. таблицу выше).
2. `libgd-tools` из trixie останется на своей версии (Depends
   `libgd3 (>= 2.1.0~alpha~)` — нас это устраивает) и продолжит работать:
   SONAME прежний, удалённых символов нет.
3. `libxpm4` пропадёт из `Depends` нашей `libgd3`. Если `libxpm4` стоял только
   ради `libgd3`, apt его снимет, а вместе с ним — `libx11-6` и прочие
   X11-пакеты, если больше никому не нужны. Это ожидаемо: репозиторий
   на чистом Wayland.

Проверить заранее:

```bash
apt-get -s upgrade
```

## Откат

Удалить репозиторий crick из источников и сделать
`apt-get install --allow-downgrades libgd3=2.3.3-14~deb13u1 libgd-dev=2.3.3-14~deb13u1`
(потребуется `libxpm4` обратно — он вернётся как зависимость trixie-сборки).
Откат X11 означает и возвращение `libxpm4` в систему: это цена отката,
а не несовместимость.
