# celluloid (crick Debian backports)

Сборка `celluloid` 0.29 для Debian 13 (trixie): графический GTK4-фронтенд для
`mpv`.

Упаковка взята из Debian (`celluloid_0.29-1`, ветка unstable) и переработана.

## Включено

- Все стандартные настройки апстрима: сборка через `dh $@ --buildsystem=meson`
  без дополнительных отключений.
- Фронтенд работает напрямую с чисто Wayland-библиотекой `libmpv2` из этого
  репозитория (см. `packages/mpv/README.md`) — в этом основной смысл сборки
  пакета здесь.
- Собирается против `libgtk-4-dev` **этого** репозитория (стадия CI 3), а не
  против GTK из trixie: в публикуемой `libgtk-4.so.1` нет символов
  `gdk_x11_*`, а линковка с `-Wl,-z,now` означала бы, что бинарь, собранный
  с X11-API, вообще не запустился бы. Патчей для этого не потребовалось: X11-
  код `celluloid` находится за `#ifdef GDK_WINDOWING_X11`, который в сборке
  GTK без X11 не определён и выключается препроцессором. `libadwaita-1-dev`
  из trixie совместим — он требует лишь `libgtk-4-dev (>= 4.17.5)`.

## Отключено

- Тестовые программы не собираются: патч `02_no-tests.patch` убирает
  `subdir('test')` из `meson.build` (опции для этого у celluloid нет), поэтому
  `test-option-parser` и `test-playlist-model` больше не компилируются.
  Документация не генерируется: готовая `celluloid.1` просто устанавливается
  из tar-бола, ничего не собирается.

## Изменено

- Версия: `0.29-2+crick` (ревизия 2 — из-за переработки упаковки).
- Патч `01_use-appstreamcli.patch`: метаданные AppStream собираются через
  `appstreamcli`, так как утилита `appstream-util`, использовавшаяся апстримом,
  в trixie больше не поставляется.
- Отладочные символы (`-dbgsym`) не собираются и не публикуются.
