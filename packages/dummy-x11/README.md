# dummy-x11

Упаковка **написана с нуля** для этого репозитория: исходников нет и быть не
может — пакет состоит только из библиотек-заглушек, которые генерируются из
списков символов, и диагностического скрипта.

## Зачем пакет

Официальный `yandex-browser-stable` из репозитория Яндекса
(`https://repo.yandex.ru/yandex-browser/deb stable main`) — бинарный пакет
без исходников. Пересобрать его без X11 нельзя, а поставить его нельзя:
`Depends` требует `libx11-6`, `libxcb1`, `libxcomposite1`, `libxdamage1`,
`libxext6`, `libxfixes3`, `libxrandr2`.

Этот пакет даёт системе недостающие имена пакетов и кладёт на место настоящих
X11-библиотек их заглушки.

## Почему не patchelf, и почему нельзя просто удалить зависимости

Первое, что приходит в голову, — `patchelf --remove-needed`. **Так не
работает**, и причина существенная:

```
$ readelf -d yandex_browser | grep FLAGS
 0x000000000000001e (FLAGS)   BIND_NOW
```

Debian собирает браузер с `-Wl,-z,now`, то есть `BIND_NOW`: динамический
линкер разрешает **все** импорты при старте, а не по первому обращению.
Удаление `NEEDED` приводит не к отложенной ошибке, а к немедленной:

```
$ patchelf --remove-needed libX11.so.6 ... yandex_browser
$ ./yandex_browser --version
symbol lookup error: undefined symbol: XFixesQueryExtension
```

Поэтому пакет кладёт на место настоящих библиотек заглушки **с теми же
SONAME**: линкер находит библиотеку по имени, все импорты разрешаются, и
программа стартует без X-сервера. Бинарник браузера и все библиотеки из его
поставки остаются нетронутыми — `patchelf` не применяется вообще.

| `…/libxcb.so.1` | заглушка вместо libxcb |
| `…/libXcomposite.so.1` | заглушка вместо libXcomposite |
| `…/libXdamage.so.1` | заглушка вместо libXdamage |
| `…/libXfixes.so.3` | заглушка вместо libXfixes |

### Символы: почему список полный, а не только используемые браузером

Заглушка экспортирует **все** символы настоящей библиотеки, а не только те
43, что зовёт браузер. Это обязательно: транзитивные X11-библиотеки ссылаются
на внутренние символы друг друга. Например `libXrender.so.1` тянет
`_XUnlockMutex_fn` из `libX11.so.6`, и заглушка с урезанным списком её ломает:

```
$ ./yandex_browser --version
symbol lookup error: /usr/lib/.../libXrender.so.1: undefined symbol: _XUnlockMutex_fn
```

Списки получены один раз с настоящих библиотек trixie через
`readelf --dyn-syms` и зафиксированы в репозитории (всего 2189 символов), так
что сборка не зависит от состава trixie.

Все эти символы — функции (проверено `readelf`: тип `FUNC`) и все без
версионных тегов, поэтому заглушки вида `void *f(void) { return NULL; }`
достаточны.

Возвращаемое значение задано явно — не «как получится». Браузер проверяет
`XOpenDisplay()` на `NULL` и по нему выбирает бэкенд; мусор в регистре
привёл бы к попытке работать через несуществующий X-сервер.

## Диагностический скрипт

Скрипт ничего не меняет в системе: вызов остаётся за пользователем.

```bash
dummy-x11-report            # полный отчёт
dummy-x11-report --brief    # сводка и недостающие символы
dummy-x11-report --snapshot # записать текущее состояние эталоном
dummy-x11-report --compare  # сравнить с эталоном (код 1 = есть новые символы)
```

Отчёт показывает:

1. версию браузера и число ELF-файлов в поставке;
2. состояние заглушек: путь, число символов, каких файлов не хватает;
3. символы: сколько X11-вызовов импортирует браузер, сколько покрыто
   заглушками, каких не хватает;
4. зависимости **по каждому файлу** поставки, с разделением:
   - `X11 (заглушки)` — закрывается заглушками этого пакета;
   - `наши из репозитория` — приходят из пакетов нашего репозитория, где X11
     уже вырезан (например `libxkbcommon.so.0`);
   - `прочие (не X11)` — ни прямо, ни косвенно с X11 не связаны, их можно
     ставить без оговорок.

## Что делать, если браузер не запускается

Браузер обновляется сам и заменяет свои файлы целиком, а заглушки живут в
отдельном пакете: новая версия может потребовать X11-вызовов, которых в
списках нет.

1. Запустить `dummy-x11-report` — он назовёт недостающие символы.
2. Дописать их в соответствующий `debian/stubs/symbols-<SONAME>.txt`.
3. Пересобрать `dummy-x11` (ревизия Debian поднимается, если список уже был
   опубликован).

Состав пакета меняется от версии к версии — это единственная причина, по
которой списки символов приходится пополнять. Режимы `--snapshot` и
`--compare` как раз для того, чтобы заметить обновление сразу: `--snapshot`
записывает текущее состояние эталоном, `--compare` затем показывает, что
изменилось, и возвращает код 1, если появились новые X11-символы.

## Побочные эффекты

- **Доступность (скринридеры) не работает.** Заглушки покрывают только
  клиентские библиотеки X11; `at-spi2-core` собирается отдельно и без X11
  (см. его README).
- Пакет конфликтует с настоящими X11-библиотеками: в системе, где X11
  используется по-настоящему, ставить его нельзя.
