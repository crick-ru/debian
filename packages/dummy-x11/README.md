# dummy-x11

Заглушки X11-клиентских библиотек для систем без X11.

Пакет заменяет восемь X11-библиотек (`libx11-6`, `libxcb1`, `libxext6`,
`libxcomposite1`, `libxdamage1`, `libxfixes3`, `libxrandr2`, `libxrandr2`)
заглушками, чтобы `yandex-browser-stable` запускался на чистом Wayland без
X-сервера.

## Источник упаковки

Упаковка написана с нуля для этого репозитория — исходников нет, пакет состоит
из заглушек, которые генерируются из списков символов реальных библиотек trixie
(`readelf --dyn-syms`).

## Версии

- **В trixie:** `libxcb1 1.17.0-2+b1` (источник для списка символов `xcb_*`)
- **В исходной упаковке:** (написана с нуля)
- **В нашем репозитории:** 1.0-10+crick

## Что изменено

- **Provides с версиями trixie для 8 пакетов:** `libx11-6`, `libxcb1`,
  `libxcomposite1`, `libxdamage1`, `libxext6`, `libxfixes3`, `libxrandr2`.
- **Conflicts/Replaces:** для всех 8 пакетов — без этого apt установил бы
  настоящие X11-библиотеки из trixie, и подмены не произошло бы.
- **libxcb — заглушка с hardcode-значениями:** 6 функций браузера
  возвращают предопределённые значения (`STUB_OVERRIDES`), остальные 676 — NULL.
  Делегирование реальной libxcb удалено.
- **Опциональное логирование:** переменная `DUMMY_X11_LOG` задаёт путь к
  файлу; если пуста — логирование не выполняется.

## Переопределённые функции libxcb


| Функция                          | Возвращает | Примечание                                          |
| --------------------------------------- | -------------------- | ------------------------------------------------------------- |
| `xcb_connect`                           | `0x1`                | non-NULL; `has_error=0` не срабатывает            |
| `xcb_connect_to_display_with_auth_info` | `0x1`                | non-NULL (редкий путь аутентификации) |
| `xcb_connection_has_error`              | `0x0`                | `XCB_CONN_SUCCESS` — no error                      |
| `xcb_generate_id`                       | `0x0`                | `InvalidXID` — signals no real X server    |
| `xcb_send_request`                      | `0`                  | error sequence — request fails                |
| `xcb_send_request_with_fds`             | `0`                  | error sequence — request fails                |
| `xcb_flush`                             | `0`                  | пусто                                                    |
| `xcb_disconnect`                        | `0`                  | void, значение не важно                        |

Одной `has_error=0x0` недостаточно: браузер всё равно 200+ раз
проверяет статус, т.к. `send_request=0` (error) приводит к постоянным
"Cannot send request" ошибкам. Текущие hardcode-значения — `generate_id=0`
(InvalidXID) и `send_request=0`, которые должны привести к ранней
терминации цикла инициализации расширений.

## Важные нюансы

- **Одна библиотека вместо шести:** все заглушки (libX11, libXext, etc.)
  собраны в один файл `dummy-x11.so` (SONAME тоже `dummy-x11.so`), а имена
  настоящих библиотек — симлинки на него. glibc не грузит один и тот же файл
  дважды (сверка `dev/inode`).
- **libxcb — отдельная заглушка** с 676 символами. 6 функций возвращают
  hardcode-значения, остальные — NULL.
- **`--disable-shlibdeps` в `dummy-x11.not-installed`:** заглушка libxcb
  имеет фиктивный SONAME и не может участвовать в dependency generation.
- **Аргументы 7+:** логирующая заглушка (только при включённом `DUMMY_X11_LOG`)
  пересылает до 6 аргументов через регистры. Аргументы через стек не
  логгируются, но это не влияет на работу заглушки — делегирования нет.
- **Оверхед логирования:** при выключенном `DUMMY_X11_LOG` функции
  заглушек не вызывают `log_entry`/`log_exit`, т.к. `g_log == NULL`.

Пакет нужен `yandex-browser-stable`, который без него не запустится и не
установится на системе без X11.
