# dummy-x11

Заглушки X11-клиентских библиотек для систем без X11.

## Источник упаковки

Упаковка написана с нуля для этого репозитория. Исходников нет — пакет
состоит из одной библиотеки-заглушки (`dummy-x11.so`) с симлинками,
логирующей заглушки `libxcb.so.1` (настоящая libxcb скрыта) и
диагностического скрипта.

## Версии

- **В trixie:** `libxcb1 1.17.0-2+b1` (используется как источник для заглушки)
- **В исходной упаковке:** (написана с нуля)
- **В нашем репозитории:** 1.0-5+crick

## Содержимое

| Файл | Назначение |
|---|---|
| `/usr/lib/x86_64-linux-gnu/dummy-x11.so` | единая библиотека-заглушка |
| `…/libX11.so.6`, `…/libXext.so.6` и др. | симлинки → `dummy-x11.so` |
| `…/libXau.so.6`, `…/libXdmcp.so.6` | симлинки → `dummy-x11.so` (для libxcb) |
| `/usr/lib/x86_64-linux-gnu/libxcb.so.1` | логирующая заглушка libxcb |
| `/usr/share/dummy-x11/hidden/libxcb-real.so.1` | настоящая libxcb из trixie (для делегирования) |
| `/usr/bin/dummy-x11-report` | диагностический скрипт |
| `/usr/share/dummy-x11/gen-stubs` | генератор заглушек |
| `/usr/share/dummy-x11/gen-libxcb-stub` | генератор логирующей libxcb |
| `/usr/share/dummy-x11/symbols-*.txt` | списки символов |

## Что изменено

- `Provides` с версиями из trixie для 9 пакетов: `libx11-6`, `libxcb1`,
  `libxcomposite1`, `libxdamage1`, `libxext6`, `libxfixes3`, `libxrandr2`,
  `libxau6`, `libxdmcp6`.
- `Conflicts`/`Replaces` с тем же набором: без них apt установил бы
  настоящие X11-библиотеки из trixie вместе с `dummy-x11`, и подмены не
  произошло бы.
- `dh_shlibdeps` отключён (`-override_dh_shlibdeps` пуст): заглушки
  `libXau`/`libXdmcp` поставляет сам `dummy-x11`, и внешних зависимостей
  у пакета нет по замыслу.
- **`libxcb — логирующая заглушка с переопределением.** Логирующая
  заглушка `libxcb.so.1` перехватывает вызовы `xcb_*` функций браузера,
  логирует их в `/tmp/dummy-x11-libxcb.log` (или `$YABROWSER_XCB_LOG` — в
  режиме append), и делегирует их настоящей libxcb из trixie по скрытому пути
  `/usr/share/dummy-x11/hidden/libxcb-real.so.1` через `dlopen`/`dlsym`. Это
  позволяет диагностировать вызовы и возвращаемые значения.
  **`xcb_connection_has_error` переопределена:** вместо делегирования
  возвращает `0x3` (`XCB_CONN_SERVER_UNAVAILABLE`) вместо `0x5`
  (`XCB_CONN_WAITING_FOR_SETUP`), который возвращает реальная libxcb.
  `0x5` заставляет браузер продолжать попытки X11; `0x3` — немедленно
  сдаться и переключиться на Wayland.

## Логгирование и переопределение libxcb

Логирующая заглушка `libxcb.so.1`:

1. При загрузке открывает файл лога в режиме **append** (`/tmp/dummy-x11-libxcb.log`
   или путь из env `YABROWSER_XCB_LOG` — режим append вместо truncate, чтобы
   не стирать записи разных процессов) и загружает настоящую libxcb через `dlopen`.
2. Для каждого из 676 символов `xcb_*` генерирует функцию-обёртку, которая:
   - захватывает аргументы из регистров (rdi, rsi, rdx, rcx, r8, r9);
   - логгирует вызов (название + аргументы);
    - **для функций из `STUB_OVERRIDES`** возвращает зарановаемое значение
      (`0x3` для `has_error`, `0x1` для `connect*`, `0xffffffff` для `generate_id`,
      `0` для `flush`/`disconnect`) — без делегирования;
    - **для остальных** функций делегирует вызов настоящей функции через
     `dlsym` с восстановлением аргументов в регистры (inline-asm);
   - логгирует возвращаемое значение;
   - возвращает результат.
3. Настоящая libxcb (`libxcb-real.so.1`) устанавливается по скрытому пути
   `/usr/share/dummy-x11/hidden/` и загружается динамически при запуске.

## Известные вызовы браузера

Из лога видно, что браузер вызывает 6 функций xcb (в порядке):

| функция | возвращает (заглушка) | примечание |
|---|---|---|
| `xcb_connect` | `0x1` | non-NULL, браузер не проверяет |
| `xcb_connect_to_display_with_auth_info` | `0x1` | non-NULL |
| `xcb_connection_has_error` | **`0x3`** | SERVER_UNAVAILABLE → Wayland |
| `xcb_generate_id` | `0xffffffff` | валидный XID |
| `xcb_flush` | `0` | пусто |
| `xcb_disconnect` | `0` | void, значение не важно |

Одной `has_error=0x3` недостаточно: браузер 200+ раз проверяет статус, но не
переходит на Wayland. Поэтому переопределены все 6 функции.

## Важные нюансы

- **Одна библиотека вместо восьми:** все заглушки (libX11, libXext, etc.)
  собраны в один файл `dummy-x11.so` (SONAME тоже `dummy-x11.so`), а имена
  настоящих библиотек — симлинки на него. glibc не грузит один и тот же файл
  дважды (сверка `dev/inode`).
-   **`libxcb` — логирующая заглушка с переопределением:** настоящая libxcb скрыта
  и делегируется через `dlopen`/`dlsym`. Экспорт всех 676 символов `xcb_*` гарантирует,
  что браузер не получит `undefined symbol`. **6 функций браузера переопределены**
  (`STUB_OVERRIDES`): `xcb_connect`, `xcb_connect_to_display_with_auth_info`,
  `xcb_connection_has_error` (→ `0x3` SERVER_UNAVAILABLE), `xcb_generate_id`
  (→ `0xffffffff`), `xcb_flush` (→ `0`), `xcb_disconnect` (→ `0`). Остальные
  670 функций продолжают логироваться и делегироваться. Одной `has_error=0x3`
  недостаточно — браузер 200+ раз проверяет статус, но не переходит на Wayland;
  поэтому переопределены все функции из лога.
- **Полный список символов:** заглушка экспортирует все символы настоящей
  библиотеки (не только те, что зовёт браузер), потому что транзитивные
  X11-библиотеки ссылаются на внутренние символы друг друга
  (`_XUnlockMutex_fn` из `libX11.so.6`). 1556 символов собираются в
  `dummy-x11.so`, список `libxcb` (676) — только для отчёта.
- **Ключевые зависимости:** настоящая `libxcb` требует `libXau`/`libXdmcp`
  по `NEEDED` (аутентификация X11), и их заглушки входят в `dummy-x11.so`.
  Функции аутентификации вызываются только при подключении к X-серверу,
  которого в целевой системе нет.
- **Аргументы 7+:** логирующая заглушка пересылает до 6 аргументов через
  регистры. Аргументы, переданные через стек (функции с >6 аргументами),
  не пересылаются — в лог попадают их значения, но делегирование может
  работать некорректно. Для большинства функций xcb это не критично.

Пакет нужен `yandex-browser-stable`, который без него не запустится и не
установится на системе без X11.
